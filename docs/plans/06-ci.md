# Plan 06 — CI build (GitHub Actions)

**Status:** live. The workflow is committed at `.github/workflows/android.yml` and has run
against the current app version. Results are in §6.
**Sign-off needed:** none (no app permission, no schema change). One owner decision: OD-2.

## 1. What the workflow does

Runs on every push, every pull request, and on demand. One job on `ubuntu-24.04`, 60-minute
limit. A newer push to the same branch cancels the older run.

| Step | Purpose |
|---|---|
| `actions/checkout@v7` | Get the code (includes 70 MB of vendored llama.cpp source). |
| `actions/setup-java@v6`, Temurin **25** | The repo pins the Gradle daemon to JDK 25 (`gradle/gradle-daemon-jvm.properties`). Installing 25 here stops Gradle downloading one at build time. |
| `gradle/actions/setup-gradle@v6` | Gradle download and dependency cache. |
| `./gradlew testDebugUnitTest` | All unit tests, including `PrivacyManifestTest` and `MigrationTest`. |
| `./gradlew assembleDebug` | Builds the APK, **including the native llama.cpp build** for two ABIs. This is the slow step. |
| Merged manifest permissions are all signed off | Second privacy gate: every `uses-permission` in the built manifest must have its own `## NAME` heading in `docs/PERMISSIONS.md`. |
| `git diff --exit-code -- app/schemas` | Fails if the build regenerated a Room schema file, which means an entity changed without a version bump and a committed schema. |
| Upload test reports (14 days) | HTML report, uploaded even when tests fail. |
| Upload debug APK (14 days) | Verification artifact. See §3. |

The runner image already has Android platform 37 and build-tools, so there is no `sdkmanager`
step.

### Why the permission step changed
The first version of this workflow failed the build if `INTERNET` appeared. That matched `main`.
The current app has eight signed-off permissions, including `INTERNET` (D26), so the gate is now
"nothing without a written sign-off". Adding a permission therefore needs a `docs/PERMISSIONS.md`
entry in the same change, or CI fails. The same rule is in `scripts/checkpoint0.sh` step 2,
checked against the app actually installed on the phone.

## 2. Network limits

| Where | Limit | Effect |
|---|---|---|
| Claude cloud sessions (where these plans were written) | The proxy blocks `dl.google.com` / `maven.google.com`. No Android SDK or NDK is installed. Maven Central answers but rate-limits. | **The app cannot be built or tested inside a Claude cloud session.** A model working there edits code and relies on CI for the result. |
| GitHub-hosted runners | Open internet. | Builds work. Robolectric downloads its `android-all` jar from Maven Central on the first run; the Gradle cache keeps it afterwards. |
| A fresh developer machine without JDK 25 | Gradle fetches a JDK from `api.foojay.io`. | First build needs network; later builds do not. |
| The app on the phone | `INTERNET` is granted for the handwriting model download (D26). | Unrelated to CI. See audit P1. |

Consequence for the handoff loop: **push → wait for CI → read the result** is the only test loop
available to a cloud session (`INDEX.md` §4). To let cloud sessions build, the owner would have to
allow `dl.google.com` and `maven.google.com` in the environment's network settings and install
the Android SDK and NDK in its setup script. That is optional, and the native build would be slow
there.

## 3. The APK from CI must not replace the installed app

Each runner signs with a new throwaway debug key. An APK signed with a different key than the
installed app cannot update it; Android asks for an uninstall, and uninstalling deletes all
notes, photos, and the AI model (audit B1). The artifact is therefore named
`app-debug-apk-DO-NOT-INSTALL-OVER-EXISTING`.

**Owner decision OD-2 — pick one:**

| Option | How | Trade-off |
|---|---|---|
| A. Mac builds are the only installed builds (default) | Nothing to do. CI is a check, not a delivery route. | Simple. The owner builds on the Mac to update the phone. |
| B. Shared debug keystore | Generate one keystore, store it base64 in a GitHub secret, point `signingConfigs.debug` at it when present, keep a copy on the Mac. | CI APKs become installable. A secret to guard. Switching keys once requires a full export, uninstall, and restore, so do it only after plan 15. |
| C. Release signing | A proper release key and `isMinifyEnabled`. | The right long-term answer; more setup. Do it before anyone else uses the app. |

## 4. Failure table

Apply a fix only if the matching failure appears, and record it in `DECISIONS.md`.

| Failure text | Cause | Fix |
|---|---|---|
| `NDK … not found` / licence not accepted | Runner lacks NDK 29.0.14206865. | Add a step before the build: `"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" "ndk;29.0.14206865"`. |
| CMake error inside `llama.cpp` | Native build problem on Linux. | Stop and report with the log. Do not edit `app/src/main/cpp/**` without a new device spike (plan 12). |
| Job hits the 60-minute limit | Native build too slow without a cache. | Add `actions/cache` for `app/.cxx` keyed on the hash of `app/src/main/cpp/**` and `app/build.gradle.kts`; or split tests and APK into two jobs. |
| "Permission without a sign-off entry" | A library merged a new permission, or one was added without the document. | This is the gate working. Follow `REVIEW_GATES.md` Gate C. |
| `git diff` step fails on `app/schemas` | An entity changed without a version bump. | Follow `14-migration-test-framework.md` §3. |
| Robolectric cannot download `android-all` | Maven Central hiccup. | Re-run once. If it repeats, report. |
| Setup-gradle licence or cache warning | v6 caching is a closed component. | Add `with: { cache-provider: basic }` to that step. |
| Serialization compiler/runtime mismatch | See `03-toolchain-report.md` §2.1. | Owner decision OD-1. |
